# 시나리오 02 — 표준용어 검색과 상세 조회

## 목적

표준프레임워크 적용 사업에서 필수인 **행정안전부 표준용어/표준단어/표준도메인**을 폐쇄망에서 본 MCP를 통해 조회할 수 있는지 확인합니다.

## 검증 도구

- `egov_search_knowledge` (scope: `terms`)

## 사전조건

- 시나리오 00 통과
- `npm run build-index`로 SQLite에 6,400+ 표준용어가 적재되어 있음

## 시나리오

### 2-1) 표준용어 키워드 검색

```text
'게시판'과 관련된 표준용어를 설명까지 포함해서 검색해줘.
```

**기대 동작**

- `egov_search_knowledge`가 `scope: "terms"`, `filters: { "fulltext": true }`로 호출됨
- 한글 표준용어 후보(예: `게시판ID`, `게시물ID`, `게시판유형코드` 등)가 다수 반환됨

### 2-2) 특정 표준용어 상세 조회

```text
표준용어 '게시판ID'의 영문명, 표준도메인, 설명을 알려줘.
```

**기대 동작**

- `scope: "terms"`, `action: "get"`, `filters: { "koreanName": "게시판ID" }`로 호출됨
- 영문 약어, 도메인(데이터타입), 설명이 포함된 응답

### 2-3) 컬럼 명명 가이드 활용

```text
"민원 신청 일시"라는 컬럼을 표준용어 명명규칙에 맞춰 영문 컬럼명으로 제안해줘. 표준용어를 근거로 보여줘.
```

**기대 동작**

- LLM이 `egov_search_knowledge`를 한 번 이상 호출하여 관련 표준용어(예: `민원`, `신청`, `일시`)를 조회
- 표준용어 결과를 근거로 `CIVIL_PETITION_REQUEST_DTTM` 류의 컬럼명 제안

## 합격 기준

- [ ] 2-1에서 최소 5건 이상의 표준용어가 반환된다.
- [ ] 2-2에서 한글 표준용어 1건의 상세 정보(영문명/도메인/설명)가 모두 표시된다.
- [ ] 2-3에서 LLM이 표준용어 검색 결과를 인용하면서 컬럼명을 제안한다(임의 추측 금지).

## 점검 포인트

- 표준용어 검색은 SQLite 기반이므로 임베딩 모델 품질과 무관하게 안정적으로 동작해야 합니다. 결과가 0건이면 `knowledge-base/egovframe.db` 적재 상태를 의심합니다.
- LLM이 "어떤 표준용어를 골라야 할지" 사용자에게 되묻는다면 결과를 좁히지 못한 것입니다. 그때는 `limit: 20` 정도로 더 넓게 검색하도록 유도합니다.
