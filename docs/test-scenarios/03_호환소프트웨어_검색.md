# 시나리오 04 — eGovFrame 버전별 호환 소프트웨어 검색

## 목적

사업 도입 단계에서 자주 묻는 "표준프레임워크 X.Y 버전과 함께 사용할 수 있는 솔루션은 무엇인가?"라는 질문에 폐쇄망 OSS LLM + 본 MCP가 답할 수 있는지 확인합니다.

## 검증 도구

- `egov_search_knowledge` (scope: `compatibility`)

## 사전조건

- 시나리오 00 통과
- 호환성 SQLite 테이블이 적재되어 있음(`npm run build-index` 결과)

## 시나리오

### 4-1) 버전 + 카테고리 조합 검색

```text
eGovFrame 4.3 버전에서 사용할 수 있는 CMS Solution을 찾아줘. 관련 개발 지식이 있으면 같이 보여줘.
```

**기대 동작**

- `scope: "compatibility"`, `filters: { "frameworkVersion": "4.3", "category": "CMS Solution", "includeKnowledge": true }`로 호출
- 제품명, 벤더, 호환 레벨이 포함된 표 형태 응답

### 4-2) 벤더 기준 검색

```text
표준프레임워크와 호환되는 한국 토종 RDBMS 제품을 알려줘. 벤더와 호환 레벨, 제품명을 같이 보여줘.
```

**기대 동작**

- `scope: "compatibility"`로 호출되며 `query` 또는 `filters.category`가 RDBMS 관련 값으로 설정됨

### 4-3) 호환 레벨 필터

```text
eGovFrame 4.3과 호환 레벨 2 이상인 솔루션 중에서 보안 관련 카테고리만 뽑아줘.
```

**기대 동작**

- `filters.minLevel: 2`, `filters.frameworkVersion: "4.3"`, `filters.category: "Security ..."` (실제 카테고리 명칭에 맞게)로 호출

## 합격 기준

- [ ] 4-1, 4-2, 4-3 각 호출에서 결과가 1건 이상 반환된다.
- [ ] 응답 표에 **버전, 제품명, 벤더, 호환 레벨**이 모두 포함된다.
- [ ] 외부 네트워크 없이 SQLite 기반으로 즉시 응답한다.

## 점검 포인트

- 호환성 카테고리 명칭은 사전에 적재된 마스터 데이터에 따라 다릅니다. LLM이 카테고리를 잘못 추론해 결과가 0건이면, `query`를 사용해 자연어 검색으로 우회하도록 유도합니다.
- `frameworkVersion` 형식은 `"4.3"`, `"4.2"`처럼 메이저.마이너 문자열입니다. LLM이 `4.3.0`로 호출하면 결과가 비어 나올 수 있으니 도구 description의 예시를 확인합니다.
