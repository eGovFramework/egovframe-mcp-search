# 시나리오 01: 공식 가이드 검색과 통합 검색

## 목적

OSS LLM이 본 MCP의 `egov_search_knowledge` 도구를 이용해 **표준프레임워크 공식 가이드**를 폐쇄망에서 검색할 수 있는지 확인합니다. 출처를 정하지 않은 질문이 통합 검색으로 처리되는지, 통합 검색에서 찾은 개발자 지식의 전체 본문을 이어서 조회할 수 있는지도 함께 확인합니다.

## 검증 도구

- `egov_search_knowledge` (`scope`: `guide`, `knowledge`, 그리고 `scope`를 생략한 통합 검색)

## 사전조건

- 시나리오 00 통과
- 설치 경로에 `knowledge-base/egovframe_guide.lance/`(공식 가이드 인덱스), `knowledge-base/developer_knowledge.lance/`(개발자 지식 인덱스), `models/`(임베딩 모델)가 있음

## 시나리오

### 1-1) 통합 검색

LLM 채팅창에 다음을 입력합니다.

```text
표준프레임워크에서 MyBatis 설정 방법을 공식 가이드와 개발자 지식에서 함께 찾아 비교해서 알려줘.
```

**기대 호출**

```json
{ "query": "MyBatis 설정 방법" }
```

**기대 결과**

- `scope`를 생략하거나 `"auto"` 또는 `"all"`로 지정한 호출은 모두 같은 통합 검색 결과를 돌려줌
- 응답이 `# 통합 지식 검색 결과`로 시작하고 공식 가이드, 개발자 지식, 공통컴포넌트, 호환 소프트웨어의 네 섹션이 차례로 나옴(출처마다 기본 5건)
- 공식 가이드 섹션(`## eGovFrame 가이드 검색 결과 (5건)`)의 결과마다 문서, 분류, 소스, URL, 유사도가 나오고, 분류는 모두 `egovframe-runtime > persistence-layer`임
- 개발자 지식 섹션(`## 개발자 지식 검색 결과`)은 JSON이며 결과마다 `id`, `title`, `content`, `tags`, `similarity`가 있음. `content`는 600자 이내의 발췌이고, 섹션 끝에 전체 본문을 보려면 `scope: "knowledge"`로 검색하라는 안내가 붙음
- 공통컴포넌트와 호환 소프트웨어 섹션은 키워드 검색이라서 문장에 가까운 `query`에는 잘 맞지 않음. 이 `query`에서는 공통컴포넌트 섹션에 부분 일치로 찾았다는 안내와 함께 일부 컴포넌트가 나오고, 호환 소프트웨어 섹션은 `"total": 0`임

### 1-2) 공식 가이드만 한정 검색

```text
표준프레임워크 공식 가이드 기준으로만 트랜잭션 설정 방법을 찾아줘. 개발자 지식이나 공통컴포넌트 검색 결과는 제외해줘.
```

**기대 호출**

```json
{ "query": "트랜잭션 설정 방법", "scope": "guide" }
```

**기대 결과**

- 응답에 `## eGovFrame 가이드 검색 결과 (5건)`만 나오고 다른 출처의 섹션이 섞이지 않음
- 명시한 `scope`는 항상 그대로 적용됨. `strictScope`는 효과가 없는 파라미터라서 LLM이 `strictScope: true`를 함께 보내도 결과는 같음

### 1-3) 분류 필터를 적용한 검색

```text
표준프레임워크 공식 가이드 중 persistence-layer 영역에서 트랜잭션을 어떻게 설명하는지 보여줘.
```

**기대 호출**

```json
{ "query": "트랜잭션", "scope": "guide", "filters": { "category": "persistence-layer" } }
```

**기대 결과**

- 결과 5건의 분류가 모두 `egovframe-runtime > persistence-layer`임
- `filters.layer: "egovframe-runtime"`을 함께 줘도 결과는 같음. `scope`를 생략해도 `category` 값이 공식 가이드의 분류이므로 가이드 검색으로 처리됨
- `layer`는 최상위 영역(`egovframe-runtime`, `egovframe-development`, `common-component`)이고 `category`는 그 아래의 분류임. `filters.layer: "egovframe-runtime"`만 주면 `foundation-layer-core` 같은 다른 분류의 문서가 섞임
- 값을 잘못 넣은 호출(예: `filters.layer: "persistence-layer"`)은 `isError` 응답으로 `알 수 없는 layer 값입니다: "persistence-layer". 사용할 수 있는 값: egovframe-runtime, egovframe-development, common-component, gettingstarted.md, _index.md, docs`를 돌려줌. LLM이 이 목록을 보고 값을 고쳐 다시 호출하는지 확인함

### 1-4) 개발자 지식의 전체 본문 조회

1-1에 이어서 다음을 입력합니다.

```text
방금 찾은 개발자 지식의 전체 본문을 보여줘.
```

**기대 호출**

```json
{ "query": "MyBatis 설정 방법", "scope": "knowledge" }
```

**기대 결과**

- 응답에 `## 개발자 지식 검색 결과` 아래의 JSON만 나오고 `resultCount`가 5임
- 1-1과 같은 글이 같은 순서로 나오며, `content`에 질문과 답변의 전체 본문이 들어 있음
- `tags`로 출처를 구분할 수 있음: `qa`는 묻고답하기, `faq`는 FAQ, `guide`와 `pdf`는 적용가이드

## 합격 기준

- [ ] 1-1에서 통합 검색 응답의 공식 가이드 섹션과 개발자 지식 섹션에 결과가 각각 1건 이상 있다.
- [ ] 1-2에서 공식 가이드 검색 결과만 반환된다.
- [ ] 1-3에서 반환된 결과의 분류가 모두 `egovframe-runtime > persistence-layer`이다.
- [ ] 1-4에서 개발자 지식의 전체 본문이 반환된다.
- [ ] 모든 호출이 외부 네트워크 없이 완료된다.

## 점검 포인트

- LLM이 "`scope`를 직접 정하라"는 안내 없이도 적절히 `scope`를 추론하는지 확인합니다. 만약 LLM이 매번 사용자에게 `scope`를 되묻는다면, 시스템 프롬프트나 도구 description이 잘 전달되지 않은 것입니다.
- 결과 응답이 너무 길어지면 `limit`을 2~3으로 줄여 다시 시도합니다. 공식 가이드와 개발자 지식의 기본값은 5건(최대 20건)이고, 통합 검색은 출처마다 5건입니다. 통합 검색에 `limit`을 주면 출처마다 그 건수가 적용됩니다.
- 통합 검색의 한 섹션에만 `검색 중 오류가 발생했습니다`가 나오면 그 출처만 실패한 것이고 나머지 섹션은 정상입니다. 오류 문구별 확인 사항은 시나리오 00의 "실패 시 대응"에 있습니다.
