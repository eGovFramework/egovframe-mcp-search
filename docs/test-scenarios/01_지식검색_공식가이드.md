# 시나리오 01 — 표준프레임워크 공식 가이드 검색

## 목적

OSS LLM이 본 MCP의 `egov_search_knowledge` 도구를 이용해 **표준프레임워크 공식 Developer Guide**를 폐쇄망에서 검색할 수 있는지 확인합니다.

## 검증 도구

- `egov_search_knowledge` (scope: `guide` 또는 `all`)

## 사전조건

- 시나리오 00 통과
- `knowledge-base/developer_knowledge.lance/`가 생성되어 있음

## 시나리오

### 1-1) 일반 지식 검색(추천 흐름)

LLM 채팅창에 다음을 입력합니다.

```text
표준프레임워크에서 MyBatis 설정 방법을 공식 가이드와 저장된 지식을 함께 찾아 비교해서 알려줘.
```

**기대 동작**

- LLM이 `egov_search_knowledge`를 `scope: "auto"` 또는 `scope: "all"`로 호출
- 결과에 공식 가이드 출처(예: `persistence-layer`, `egovframe-runtime` 레이어)가 포함됨
- 응답이 한국어로 정리되어 사용자에게 표시됨

### 1-2) 공식 가이드만 한정 검색

```text
공식 eGovFrame Developer Guide 기준으로만 트랜잭션 설정 방법을 찾아줘. 개인 지식이나 공통컴포넌트 검색 결과는 제외해줘.
```

**기대 동작**

- LLM이 `scope: "guide"`와 `strictScope: true`를 함께 지정해 호출
- 응답에 공식 가이드 외 다른 출처가 섞이지 않음

### 1-3) 레이어 필터를 곁들인 검색

```text
표준프레임워크 공식 가이드 중 persistence-layer 영역에서 트랜잭션을 어떻게 설명하는지 보여줘.
```

**기대 동작**

- 호출 인자에 `filters.layer: "egovframe-runtime"` 또는 `filters.category: "persistence-layer"`가 포함됨

## 합격 기준

- [ ] 1-1, 1-2, 1-3 각 호출에서 1건 이상의 가이드 청크가 반환된다.
- [ ] 1-2에서 `strictScope: true`가 적용되어 다른 scope 결과가 섞이지 않는다.
- [ ] 모든 호출이 외부 네트워크 없이 완료된다(시나리오 09에서 별도 검증).

## 점검 포인트

- LLM이 "scope를 직접 정하라"는 안내 없이도 적절히 scope를 추론하는지 확인합니다. 만약 LLM이 매번 사용자에게 scope를 되묻는다면, 시스템 프롬프트나 도구 description이 잘 전달되지 않은 것입니다.
- 결과 응답이 너무 길어지면 `limit`을 5 정도로 좁혀 다시 시도합니다.
