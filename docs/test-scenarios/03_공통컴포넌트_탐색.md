# 시나리오 03 — 공통컴포넌트 탐색과 활용

## 목적

표준프레임워크 공통컴포넌트 자산을 폐쇄망에서 본 MCP를 통해 **검색 → 상세 조회 → 의존성 확인 → 소스/DDL 조회**의 흐름으로 활용할 수 있는지 확인합니다.

## 검증 도구

- `egov_search_knowledge` (scope: `components`)

## 사전조건

- 시나리오 00 통과
- `templates/common-components-src/`와 공통컴포넌트 메타데이터가 정상 로드됨

## 시나리오

### 3-1) 자연어로 공통컴포넌트 찾기

```text
게시판 기능을 구현할 때 참고할 만한 표준프레임워크 공통컴포넌트를 찾아줘. 컴포넌트 ID와 짧은 설명도 알려줘.
```

**기대 동작**

- `egov_search_knowledge`가 `scope: "components"`, `query: "게시판"`으로 호출됨
- `bbs`, `bbsuse`, `cmt` 등 공통컴포넌트 후보가 반환됨

### 3-2) 컴포넌트 상세 조회

```text
bbs 공통컴포넌트의 구조와 의존성, 사용 테이블을 정리해서 보여줘.
```

**기대 동작**

- `action: "get"`, `filters: { "componentId": "bbs" }` 호출 1회
- `action: "dependencies"`, `filters: { "componentIds": ["bbs"] }` 호출 1회

### 3-3) 소스 파일 목록과 단일 파일 조회

```text
bbs 공통컴포넌트에 어떤 Java/Mapper XML/JSP 파일이 있는지 목록을 보여주고, 그 중 게시글 등록 컨트롤러 한 파일을 열어서 어떤 메서드가 있는지 요약해줘.
```

**기대 동작**

- `action: "sourceFiles"`로 파일 목록 조회 → `action: "readSource"`로 컨트롤러 한 파일 조회 → LLM이 메서드 시그니처 요약

### 3-4) DDL / DML 조회

```text
bbs 공통컴포넌트가 필요로 하는 MySQL 테이블 생성 DDL과 초기 데이터 DML을 추출해줘.
```

**기대 동작**

- `action: "ddl"`, `filters: { "componentId": "bbs", "dbType": "mysql" }` 호출
- `action: "dml"`, `filters: { "componentId": "bbs", "dbType": "mysql" }` 호출
- 두 호출 모두 SQL 텍스트가 반환됨

## 합격 기준

- [ ] 3-1에서 게시판 관련 공통컴포넌트가 1건 이상 반환된다.
- [ ] 3-2에서 컴포넌트 정보와 의존성 그래프가 모두 응답에 포함된다.
- [ ] 3-3에서 LLM이 소스 파일 본문을 읽은 뒤 메서드를 요약한다(추측이 아닌 인용).
- [ ] 3-4에서 `CREATE TABLE` 또는 `INSERT INTO` SQL이 반환된다.

## 점검 포인트

- 공통컴포넌트 ID를 모를 때는 자연어 검색을 먼저, ID를 알 때는 `action: "get"`을 바로 사용하도록 LLM이 분기하는지 봅니다.
- `dbType`을 변경(`oracle`, `postgres` 등)했을 때도 동일한 흐름이 동작하는지 추가 검증 가능합니다.
