# 폐쇄망 OSS LLM + eGovFrame MCP 테스트 시나리오

본 폴더는 **폐쇄망 환경에서 OSS LLM(예: Llama, Qwen, Mistral 등)과 eGovFrame MCP Search**(`egovframe-mcp-search`)를 연동해 표준프레임워크 지식베이스에 접근할 수 있는지 검증할 때 사용하는 시나리오 모음입니다.

## 목적

- 본 MCP가 외부 네트워크 없이 `egov_search_knowledge` 한 도구로 동작하는지 확인합니다.
- 공식 가이드, 개발자 지식(포털의 묻고답하기·FAQ·적용가이드), 공통컴포넌트, 호환 소프트웨어의 네 출처가 이 도구의 `scope`와 `action`으로 올바르게 조회되는지 검증합니다.

## 전제

- 폐쇄망 서버에 Node.js 22가 설치되어 있습니다. 배포본에 동봉된 `better-sqlite3` 네이티브 바이너리가 Node.js 메이저 버전에 고정되어 있어서, 다른 버전에서는 서버가 시작되더라도 SQLite를 쓰는 조회(공통컴포넌트, 호환 소프트웨어 등)가 실패합니다.
- 서버의 OS와 CPU에 맞는 배포 tgz(`npm run pack:platforms`의 산출물)를 폐쇄망으로 반입해 설치한 상태입니다. 배포 tgz에는 빌드 결과, 의존성, 지식베이스, 임베딩 모델, 공통컴포넌트 소스가 들어 있으므로, 폐쇄망에서는 설치한 뒤에 `npm install`, `npm run build`, `npm run build-index`를 실행하지 않습니다. 설치 절차는 [00_사전준비.md](./00_사전준비.md)에 있습니다. 이 시나리오 문서도 배포 tgz의 `docs/test-scenarios/`에 들어 있습니다.
- OSS LLM이 MCP 클라이언트에 연결되어 있고, 그 클라이언트에 본 MCP 서버가 stdio 방식으로 등록되어 있습니다.

## 수행 방법

각 단계에는 LLM 채팅창에 입력할 프롬프트, 기대 호출(도구에 넘기는 인자), 기대 결과가 적혀 있습니다. 프롬프트를 입력한 뒤 클라이언트의 호출 기록에서 LLM이 보낸 인자를 기대 호출과 비교하고, 도구 응답을 기대 결과와 비교합니다. LLM이 다른 인자를 골랐다면 기대 호출의 인자를 그대로 쓰도록 요청해서 도구의 응답을 따로 확인합니다.

- 기대 결과에 적힌 건수와 이름은 배포본에 동봉된 데이터 기준입니다. `update` 명령으로 지식베이스를 갱신한 환경에서는 갱신분이 먼저 쓰이므로 건수와 이름이 다를 수 있습니다.
- 기대 호출에 `<...>`로 적은 값은 바로 앞의 응답에서 복사해 넣는 값입니다. 공식 가이드 청크의 `chunkId`가 그런 값이며, 지식베이스를 갱신하거나 다시 구축하면 바뀌므로 문서에 고정된 값으로 적지 않았습니다.
- 필터는 모두 `filters` 객체 안에 넣습니다. LLM이 `frameworkVersion`이나 `componentId` 같은 필터 키를 인자의 최상위에 두면 그 키는 입력 검증 오류 없이 버려집니다. 그래서 필터가 적용되지 않은 결과가 나오고, 그 필터가 있어야 하는 조회는 `filters.componentId is required for component detail lookup` 같은 오류로 응답합니다. 응답이 기대 결과와 다르면 호출 기록에서 필터가 `filters` 안에 있는지 먼저 확인합니다.
- LLM이 쓰지 않는 파라미터(`query`, `scope`, `action`, `limit`)나 `filters` 안의 필터를 `null`이나 빈 문자열로 채워 보내도 결과는 같습니다. 서버가 그런 값을 지정하지 않은 것으로 처리하므로 기대 호출과 같은 호출로 봅니다. 다만 `filters` 자체는 객체이거나 `null`이어야 하며, 빈 문자열(`"filters": ""`)을 보내면 입력 검증 오류가 됩니다.

## 평가 양식

각 시나리오마다 아래 항목을 기록합니다.

- 시작 시각 / 종료 시각
- 사용한 OSS LLM 모델명과 파라미터(temperature 등)
- 입력한 자연어 프롬프트 원문
- MCP 호출 로그(가능하면 도구명·인자 캡처)
- 응답 요약
- **합격/불합격** 판정 및 근거
- 발견된 이슈 또는 개선 의견

## 사용 권장 순서

1. **00**: 폐쇄망 환경 자체가 의도대로 구성되었는지 먼저 확인합니다.
2. **01 ~ 03**: 통합 검색과 `scope` 값 `guide`, `knowledge`, `components`, `compatibility`에 대해 LLM이 본 MCP의 지식베이스에 정상적으로 접근하는지 검증합니다.
